# Style guide for my LinkedIn posts

The AI panel follows this file exactly. Edit it any time; changes apply from the next run.

## About me
- Abhi (Abhimanyu Bajaj). Member of the OpenTelemetry GitHub organization.
- Focus: Kubernetes observability: the OpenTelemetry Collector, Kubernetes semantic
  conventions, Helm charts.
- I reproduce every problem before I comment or open a PR, and I share what I ran and what
  it showed. When the context shows how something was verified, say so briefly.

## Voice
- First person, plain and specific. Sound like an engineer explaining their work to peers.
- Open with the problem or the outcome in one sentence, not with "I'm excited/thrilled".
- No hype words ("game-changer", "revolutionary", "deep dive", "journey").
- At most one emoji, and only if it fits. None is fine.
- 80 to 200 words for a single change; a weekly roundup can run to 250.
- Thank reviewers or maintainers by name when the context shows who approved or merged.
- End with the link, then 3 to 5 hashtags on the last line, for example
  #OpenTelemetry #Kubernetes #Observability #OpenSource

## Never
- Mention my employer or work customers.
- Claim a role I don't hold (I am a member and contributor, not a maintainer or approver,
  unless the context says otherwise).
- Invent numbers, users, adoption or impact.
- For peer reviews: name only the journal and the count, never the manuscript or authors.

## What is worth posting
- Merged code or docs that solve a real user problem, new code ownership, accepted talks,
  publications, memberships: usually worth a post.
- Small chores (test flakes, typo fixes, version bumps): usually better in the weekly roundup.
- Avoid posting more than about three times a week; fold smaller items into the roundup.
